# CPA 渠道账号管理

New API 的管理员及超级管理员从“渠道 → CPA 账号”访问本实例关联的 CPA。CPA 持有 OAuth 凭据，并在选中具体凭据后控制并发。一个 New API 实例目前管理一个独立运行的 CPA。单账号并发按 CPA 进程和凭据 ID 计数，多个 CPA 副本或同一账号的重复凭据会分别计数。

| New API 环境变量 | 用途 |
| --- | --- |
| `CPA_MANAGEMENT_URL` | 可信 CPA 服务地址，例如同一 Docker 内网的 `http://cli-proxy-api:8317` |
| `CPA_MANAGEMENT_TOKEN` | CPA 管理接口凭据，由部署环境注入 |
| `CPA_RELAY_URLS` | 该 CPA 的其他转发地址，以逗号分隔。渠道列表用这些地址和管理地址匹配渠道，保留服务子路径，兼容末尾的 `/v1` |
| `CPA_CHECK_INTERVAL` | 主节点轮询间隔，例如 `30m`，至少一分钟。留空关闭轮询 |
| `CPA_CHECK_MODEL` | 已授权用于检查的模型名。留空关闭轮询 |

新建 OpenAI 兼容渠道时，填写上述 CPA 的转发地址和业务 API Key。默认的“创建专属号池”会同时在 CPA 建立空池并保存渠道绑定。要共享已有池，在创建页选“与某渠道共享号池”。即使同名或复制渠道，默认仍各有独立号池。改名保留绑定。部署前已存在的渠道继续使用原有公共池。

在渠道行点击账号数，空池显示“暂无账号 · 添加账号”。在弹窗点“添加授权账号”，由持有人在供应商页面登录，将回调粘回原会话并继续。CPA 保存凭据及渠道号池归属。重复授权其他池的同一凭据会提示冲突。Plus、Pro、降质可作为账号订阅分类；渠道调度使用保存在数据库的号池 ID。

配套 CPA 的独立实例支持专属池的模型列表、Chat Completions、Completions、Responses 和 Responses Compact HTTP 接口，包括支持流式响应的接口。New API 会自动使用绑定的池地址。空池的推理返回 HTTP 503；一次请求选定专属池后，New API 停止跨渠道重试。旧的通用地址使用公共池凭据。渠道页只统计本池账号；显式共享的渠道显示相同统计。并发上限 `0` 表示不限，达到正数上限的请求等待名额或由客户端取消。

“问题账号”显示需要重新登录、已停用或最近一次检查异常的账号。CPA 明确标记需要重新登录时，检查任务会停用该凭据。答题不符、限流和暂时无法判断分别记录，管理员可以从列表单独停用账号。答题结果本身不能证明供应商实施了风控。轮询会消耗模型额度。

从具体渠道的账号窗口点 **批量导入 JSON**，可多选标准 CPA Codex 账号备份文件，也可选择包含多个账号对象的 JSON 数组。每个文件最大 8 MiB，每个账号最大 128 KiB。新导入账号先停用，核对后点该行的 **启用**。已有账号会跳过。SIWC 专用凭据请使用登录授权。

在渠道账号窗口顶部设置「本池每账号并发上限」，一次保存即对池内每个账号分别生效，之后授权或导入的账号自动继承。共享同一号池的渠道共用这个值。首次设置前沿用各账号旧值，明确填 0 表示全池每个账号均不限。

## 渠道巡检

管理员打开「渠道 → 渠道巡检」，每个绑定 CPA 号池的渠道都有独立卡片。展开「巡检设置」可填测试模型、间隔、题目及标准答案，保存后可立即巡检。默认手动运行，预填间隔 30 分钟。开启自动巡检后，New API 主节点每分钟检查到期渠道，同一渠道在上一轮完成后按设置的间隔再次执行。每轮轮换一道题，CPA 逐个测试该池已启用账号，完整答复去掉首尾空白后与标准答案比对。限流、答题不符、需要重新登录和无法判断分别记录。测试会消耗所选模型额度。

「渠道并发上限」控制单个 New API 进程中该渠道同时处理的模型请求，包含流式响应和巡检探测。0 表示不限。CPA 仍执行账号维度的并发上限。勾选「向客户展示」并设置显示名后，登录客户可从侧栏「渠道巡检」查看最近一轮的匿名账号结果，管理员另可看到账号标签、测试题和模型。

## 发布与回滚

先记录两个生产容器当前镜像的不可变摘要，并备份配置、CPA 授权目录和 New API 数据库。用隔离的数据库、Redis 和 CPA 授权目录验证两份候选镜像。若加载原有 CPA Go 插件，还需验证原 `.so` 的 Go 工具链和依赖兼容。通过测试后，在有独立 SSH 控制通道的维护窗口切换流量。首次发布时留空轮询间隔，先核对账号、授权和排队行为。

回滚时将流量切回原实例及已记录的镜像摘要。已停用状态保存在 CPA 凭据中，切换镜像后仍需核对。保留授权数据和问题记录。当前聊天依赖生产 New API 和 CPA，切换前应准备另一个不依赖这组服务的操作通道。
